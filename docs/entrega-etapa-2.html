1. Continuidad con la Etapa 1

Se conserva y corrige la API de la Etapa 1. El recurso principal Book mantiene sus campos, DTOs y códigos de respuesta. Los cambios documentados son:

  • GET /books ahora es paginado, filtrable y ordenable y devuelve { data, meta }.
  • Los endpoints de escritura de libros quedan protegidos con JWT.

No se reinició ni sustituyó el trabajo de la etapa anterior.

2. Modelo relacional

Además de Book y de User, se agregaron dos entidades de dominio: Loan (préstamo) y Fine (multa).

Entidades y campos

EntidadTablaCampos relevantes
Bookbooksid, title, author, isbn (único), category, year, copies
Userusersid, name, email (único), password (hash, nunca se devuelve), role, createdAt, updatedAt
Loanloansid, book_id (FK), user_id (FK), loanDate, dueDate, returnDate, status
Finefinesid, loan_id (FK), amount, reason, paid, createdAt

Relaciones y reglas de borrado

RelaciónTipoRegla de borradoJustificación
User → LoanOneToMany / ManyToOneON DELETE CASCADEAl eliminar el usuario sus préstamos dejan de existir.
Book → LoanOneToMany / ManyToOneON DELETE RESTRICTNo se borra un libro con historial de préstamos; la API responde 409.
Loan → FineOneToMany / ManyToOneON DELETE CASCADELa multa no existe sin el préstamo que la origina.

Los datos relacionados no se duplican: loans guarda book_id y user_id (no el título ni el correo) y fines guarda loan_id.

3. Migraciones y configuración

El esquema se crea con una migración versionada (1791774691127-InitialSchema.ts) y synchronize está fijo en false. La configuración se lee desde variables de entorno; solo se publica .env.example (sin secretos).

npm install
cp .env.example .env      # completar credenciales
npm run migration:run     # aplica el esquema versionado
npm run start:dev

Variables: PORT, DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME, DB_SYNCHRONIZE=0, JWT_SECRET, JWT_EXPIRES_IN.

4. Endpoints protegidos (JWT)

Se protegen todos los endpoints de escritura más las consultas de usuarios. Se demuestra la diferencia entre una petición sin token y una autenticada.

6. Evidencias de ejecución

6.1 Registro seguro

POST /auth/register
{ "name": "Ana Librera", "email": "ana@biblioteca.com", "password": "Secreta123" }

201 Created
{ "id": 1, "name": "Ana Librera", "email": "ana@biblioteca.com", "role": "reader" }
(sin campo "password")

6.2 Login y emisión de JWT

POST /auth/login
{ "email": "ana@biblioteca.com", "password": "Secreta123" }

200 OK
{ "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", "tokenType": "Bearer",
  "expiresIn": "1h", "user": { "id": 1, "name": "Ana Librera", "role": "reader" } }
POST /auth/login con contraseña incorrecta -> 401 Unauthorized

6.3 Petición sin token vs autenticada

POST /books  (sin Authorization)
401 Unauthorized
{ "message": "Unauthorized", "statusCode": 401 }

POST /books  (Authorization: Bearer <token>)
201 Created
{ "id": 1, "title": "Clean Code", "author": "Robert C. Martin",
  "isbn": "9780132350884", "category": "Tecnologia", "year": 2008, "copies": 5 }

6.4 Relación persistente (préstamo que asocia libro y usuario)

POST /loans  (con token)
{ "bookId": 1, "userId": 1 }

201 Created
{ "id": 1,
  "book": { "id": 1, "title": "Clean Code" },
  "user": { "id": 1, "name": "Ana Librera", "email": "ana@biblioteca.com" },
  "loanDate": "...", "dueDate": "...", "returnDate": null, "status": "active" }
GET /users/1/loans  -> lista los préstamos del usuario (datos relacionados)
GET /books/1/loans  -> lista los préstamos del libro (datos relacionados)
DELETE /books/1 con préstamo asociado (RESTRICT) -> 409 Conflict
{ "message": "No se puede eliminar el libro 1 porque tiene prestamos asociados" }

6.5 Filtros, ordenamiento y paginación

GET /books?page=1&limit=2&sortBy=title&order=DESC

200 OK
{
  "data": [ { "id": 3, "title": "Libro 3" }, { "id": 2, "title": "Libro 2" } ],
  "meta": { "page": 1, "limit": 2, "total": 3, "totalPages": 2,
            "hasNextPage": true, "hasPrevPage": false }
}
GET /books?category=Novela            -> filtra por categoría
GET /books?search=clean               -> busca en título, autor e ISBN
GET /loans?status=active&sortBy=loanDate&order=DESC
GET /fines?paid=false                 -> multas no pagadas
GET /books?page=abc                   -> 400 (validación de query params)
